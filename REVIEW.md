## Архитектура

Браузер → nginx → HTTP API. Frontend знает публичный контракт, адреса внутренних
сервисов отсутствуют. nginx отдаёт статику, Go отвечает только за API/медиа/транспорт.
В compose только nginx имеет опубликованный loopback-порт.

`cmd/server` — точка входа; `platform/services` создаёт зависимости и управляет
runtime; контроллеры получают готовые сервисы через `Config`. Домены auth, catalog,
scores имеют реальные `controller`, `services`, `repo`, `test`. Stateless handshake
не имеет искусственного репозитория. JSON-хранилища рассчитаны на один процесс API.

## Авторизация

Реализованы локальные аккаунты и серверный Google OAuth. Пароли: независимые соли,
PBKDF2-HMAC-SHA256 600 000 итераций, одинаковая dummy-проверка для неизвестного
пользователя, ограничение попыток и вычислений. Dummy hash уменьшает различие
стоимости ответа; он не заменяет стойкий пароль. Это соответствует назначению
generic responses/timing mitigation в [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html).

Google OAuth проверяет PKCE/state/nonce и подписанный ID token. Доверенный субъект
— Google `sub`; одного email из запроса недостаточно. Настройка redirect URI и
секретов описана в README; протокол сверялся с [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect).

## Что требует конфигурации или сохраняет ограничения

- Нужны собственные `PM_GOOGLE_CLIENT_ID` / `PM_GOOGLE_CLIENT_SECRET`. Реальный вход в Google с учётной записью пользователя не выполнялся; callback и отрицательные криптографические сценарии проверены тестами с тестовым transport.
- Docker CLI отсутствует в текущей среде: контейнерная сборка не запускалась. Dockerfiles/compose подготовлены, приложение и nginx проверены нативно.
- Для публичного размещения нужен HTTPS ingress и корректный `PM_PUBLIC_URL`. По умолчанию доступ только с localhost.
- Отдельный admin secret подтверждает знание ключа, не аппаратную идентичность устройства. Локальные email не подтверждаются письмом и не дают административной роли по email.
- Общая таблица любительская: результат вычисляет браузер, сервер проверяет владельца и диапазон, но не воспроизводит партию. Для соревнований нужен серверный протокол игры.
- Каталог исходного проекта содержит демо-пакеты. Оригинальные APK/EXE отсутствуют и должны добавляться владельцем; автоматическая установка на устройство не выполняется.
- Сессии и лимиты находятся в памяти одного процесса; рестарт отзывает сессии. Горизонтальное масштабирование требует общей БД/хранилища сессий.
- Исправлены конкретные причины лишней работы и зависаний. Сравнительных измерений FPS и нагрузочного тестирования production нет.
